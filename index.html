Les registres de la table

Cinq outils pour jouer, solo avec l’Oracle ou à plusieurs : créer ses Marchefleurs, tenir la partie séance après séance, garder trace de ceux qu’on croise, faire progresser les personnages, tirer ce qui se dresse sur la route.

Registre de la Table la partie Pendant la séance, tout au même endroit : le compte rendu avec les jets, les dégâts et les PV dedans, les dés lancés ici ou sur la table, le combat et le butin à côté du récit, la compagnie. À plusieurs, chacun sur son ordinateur. Registre des Visages les PNJ Une fiche pour chaque personne croisée, ses liens avec les autres et avec les personnages, le réseau qu’ils dessinent et l’histoire de ces liens. Chaque fiche regroupe ce que les comptes rendus disent d’elle. Registre de la Progression la progression Les points que rapportent les missions, et ce qu’on en fait au prix du livre : compétences, Pratiques de son domaine, caractéristiques, PV. Chaque achat s’écrit dans la séance. Registre du Havre les personnages Créer un personnage selon le livre et le garder dans tes personnages, l’imprimer, l’exporter en Word, ou l’enregistrer en .json pour le faire entrer dans la Table. Registre des Rencontres les adversaires Tirer une rencontre à la mesure du groupe et la mettre dans la séance en un clic, tenir le bestiaire maison, ses familles et ses tables de butin, retoucher les entrées du livre.

Tout garder en ligne

Sans rien relier, chaque registre garde ce que tu fais dans ce navigateur, et seulement là : un nettoyage du navigateur, un autre ordinateur, et tout est à refaire. Relie une fois un dépôt GitHub privé : la table et ses PNJ, tes personnages et ton bestiaire y partent tout seuls, et tu les retrouves partout où le dépôt est relié.

Dans le dépôt

    Mettre le dépôt en place

    1. Sur GitHub, crée un dépôt privé, faelorenn-table par exemple, et coche « Add a README file » pour qu’il ne soit pas vide.
    2. Crée un jeton : Settings, Developer settings, Personal access tokens, Fine-grained tokens, Generate new token. Dans Repository access, choisis seulement ce dépôt. Dans les permissions du dépôt, mets Contents en Read and write. Donne-lui une date d’expiration.
    3. Colle le dépôt et le jeton ci-dessus, puis « Relier ». Les registres de ce navigateur s’en servent aussitôt.
    4. Donne le même dépôt et le même jeton à ceux qui jouent avec toi, par un message privé. Un jeton à accès fin ne sert que pour les dépôts de son propriétaire : les autres ne peuvent pas s’en faire un pour le tien.

    Le jeton n’ouvre que ce dépôt-là, et il reste dans le navigateur où on l’a collé. S’il se perd, supprime-le sur GitHub et crée-en un autre : rien de ce qui est dans le dépôt n’en souffre.

    Chaque enregistrement devient une version dans l’historique du dépôt. Les registres regroupent les changements et n’écrivent jamais deux fois en moins de quinze secondes : GitHub en accepte 500 par heure et par jeton, ce qui laisse de la marge même à plusieurs pendant une séance chargée.

    Jouer à plusieurs

    Pour la table, trois chemins :

    1. Par la sauvegarde en ligne. Chacun relie le même dépôt. Chaque changement y part tout seul, et les autres le reçoivent dans les dix à trente secondes.
    2. Par un dossier partagé. Le fichier de table posé dans Drive, OneDrive ou Dropbox, synchronisé sur chaque ordinateur. Il faut Chrome ou Edge, et le fichier posé sur l’ordinateur plutôt que le site.
    3. Par un .json. On l’enregistre, on l’envoie, l’autre l’importe. Tout se fusionne sans rien écraser.

    Ce que ce site montre

    Le site est public : avec un compte GitHub gratuit, le dépôt qui l’héberge doit l’être, et n’importe qui peut lire le code des registres, avec ce qu’il contient du livre (peuples, Pratiques, bestiaire).

    Vos personnages, vos séances et votre bestiaire ne sont jamais dans ce dépôt-là. Ils restent dans vos navigateurs, et dans votre dépôt privé si vous reliez la sauvegarde en ligne.
